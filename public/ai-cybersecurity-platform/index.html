AI cybersecurity platform

Use this desk before a model is connected to company data. Write down what it can reach, who can invoke it, and where the log goes. The page does not open ports, scan hosts, or try prompts against a live system.

Systems

Name each model, the vendor, and the environment (laptop, tenant, or VPC). One row per system is enough to start.

Data

List the stores the system can read or write: mail, tickets, files, customer records. If you cannot name the store, it is not ready to connect.

People

Who may invoke it, who can change the prompt or the tool list, and who is called when it does something unexpected.

Checks to finish before go-live

  • The certificate name matches the hostname people actually type. Use the certificate checklist.
  • An incident owner and a phone number are written down. Start from incident response or the runbook generator.
  • A review of scope, evidence, and stop rules exists. Use the scoping worksheet. It does not contain attack text.
  • Vendor questions live on cybersecurity services.
