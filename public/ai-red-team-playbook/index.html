AI red-team scoping playbook

Use this worksheet before anyone tests a model that can see customer data. It records who authorized the test and what evidence to keep. It does not include attack strings, jailbreak text, or payloads. Those stay inside an engagement with a named owner. Defensive checks you can run yourself are on Prompt Shield.

Name the system

Write the model, the tool it can call, and the data class it can read. If you cannot name the data class, the test waits.

Name the authorizer

One person signs the window: start, stop, and which environments are in bounds. Production customer actions are out of bounds unless that sentence is in the note.

Evidence, not a trophy

Keep the prompt id, model version, time, and the outcome a reviewer can replay. Drop screenshots that contain secrets.

Stop rules

Stop when the test would email a customer, move money, change a production config, or touch data you did not list. Log the stop. Do not improvise a second path.

Questions by industry

Healthcare

Would this test read or write PHI? If yes, the healthcare hub and a BAA conversation come before any prompt. Healthcare IT

Finance

Would this test place, hold, or release a payment? If yes, it is a process review, not a playground. Fintech IT

Support

Would this test send a message a customer can see? Draft it in a closed queue first. Support deflection desk
