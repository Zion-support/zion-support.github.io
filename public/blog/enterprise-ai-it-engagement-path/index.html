Why enterprise work leans Consulte

A published Starter SKU feels like progress because a card can move. The usual failure is commercial, not technical:

  • Program language without a slice. “Enterprise AI” or “modernize IT” is a wish list. Nobody wrote one owner or one KPI.
  • MSA becomes the strategy. Keep-vs-send was never decided, so every new request lands on the paper by default.
  • No exit. Knowledge, admin rights, and the exception queue stay with the vendor because the SOW never named an acceptor on your side.
  • Politics before access. Security, finance, and ops have not agreed what a helper may read or write. A $2,500 kickoff will stall on the first ticket.

That is why this page leans Consulte. Signing first and scoping later is how program MSAs expand. Consulte names outcomes, owners, and edges. One owner + one KPI before any ZG06

The Pay path is allowed only when the slice is already namable. That is not a slogan. It is a gate:

  • One owner — a named person who can grant access for the pilot window and sign that the deliverable matches the SOW. Not a steering committee of five.
  • One KPI — one operating signal you already measure on that slice. Queue time on a named queue. Exception rate on a named loop. Spend alerts on a named envelope. We will not invent a program savings percentage to justify the buy.
  • Narrow slice — one process, one system of record, one definition of done. Not “phase 1 of the AI program.”
  • Never a program MSA. If procurement wants a blanket paper that covers “all AI / IT,” that conversation is Consulte. ZG06 cannot be the paper.

If those four are true, a Consulte workshop that restates the same slice is optional, not required. Many buyers still run Discovery as a cheap confirmation before ZG06 — that is fine. What is not fine is skipping the gate when none of the bullets above are true.
