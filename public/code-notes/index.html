Code notes

A brief you fill in before anyone changes a repository. Nothing is committed, reviewed, or deployed from this page.

What to write down

  • The repository, the branch that may change, and the person who can merge.
  • Which files are in scope, and which directories stay untouched.
  • How a change is checked: the test command you already run, and who reads the diff.
  • What a failed check does. The change stays in draft until a person says otherwise.

Where the older host breaks

  • The code-assistant host opens, and its About, Contact, Blog, and Services paths return 404.
  • Use the notes on this site. A pull-request brief is already at the pull request notes.
