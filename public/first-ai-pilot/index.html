Your first AI pilot

The best first AI use case is usually a bounded workflow with a measurable result and a human reviewer. Before choosing a model or agent framework, write a short brief that someone outside the project can understand.

Describe the work before naming the technology

State what arrives, what should come out and which decisions must stay with a person. Explain the common case and the exceptions. For a support workflow, for example, a pilot might suggest a category and draft a response while an authorized employee still approves the message. Do not start by authorizing an agent to contact customers or change production systems automatically.

Define the data the pilot actually needs. Use synthetic or approved, minimized examples during evaluation. Separate public reference material from customer information, credentials and regulated records. Document who may access the pilot and how test data will be removed.

Define success and failure

Select a small set of representative cases and decide how they will be scored. Measure correctness, the time reviewers spend checking output, the frequency of exceptions and the cost of running the workflow. A lower model price is not a saving if the review effort increases or an unsafe action becomes more likely.

A recommendation is not an integration. When browsing the Apps Network, ask whether a page is a working interface, a concept, a prototype or a service description. Check the actual functionality before including it in a delivery plan. Do not treat a catalog description as evidence of installed monitoring, security testing, automation or a service-level commitment.

Keep a person in charge of the release decision

Write the approval step, the permitted actions and the rollback path. Decide what happens when an input is missing or a response is uncertain. Sending messages, placing orders, deleting information and changing production should require the appropriate explicit authorization.

Use the free online Discovery questionnaire to organize the initial sector, challenge, timeline, desired outcome and deployment preference. The questionnaire currently opens in Portuguese and provides rules-based recommendations after submission. Its email-copy request should not be interpreted as confirmed receipt by both inboxes.

You can stop after the free discovery. Any paid pilot or implementation should have its own scope, acceptance criteria, price and approval. A clear “not yet” can be a better outcome than automating an unready workflow.
